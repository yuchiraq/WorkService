# Подключение облака к файловым приложениям

WebDAV предоставляет **то же личное облако администратора**, не отдельную
серверную папку. Адрес после включения:
`https://appworks.avayusstroi.by/dav/`.

## iPhone и iPad

Google Drive появляется в приложении «Файлы» благодаря установленному приложению
Google Drive с расширением File Provider. Веб-сайт или установленная PWA сами по
себе такое расширение добавить не могут.

Для WebDAV нужно приложение, которое поддерживает **и WebDAV по HTTPS, и
интеграцию с системными «Файлами»**. Не каждый WebDAV-клиент умеет второе.
После настройки сервера в приложении включите его расположение в «Файлы →
Обзор → … → Изменить». Для подключения используются адрес, логин и отдельный
пароль устройства из «Моё облако → Подключения».

Без стороннего файлового приложения альтернативы: собственное нативное
приложение WorkService с File Provider или SMB через VPN. Они не входят в эту
реализацию. Встроенное «Подключиться к серверу» не заменяет WebDAV-провайдер.

## Windows: сетевой диск

При наличии работающей службы **WebClient** в Проводнике выберите
«Этот компьютер → Подключить сетевой диск», свободную букву и путь:

```text
\\appworks.avayusstroi.by@SSL\DavWWWRoot\dav
```

Укажите отдельные учётные данные: логин WorkService и пароль устройства,
не основной пароль аккаунта. Вариант через терминал с интерактивным вводом
пароля (буква W должна быть свободна):

```powershell
net use W: "\\appworks.avayusstroi.by@SSL\DavWWWRoot\dav" /user:ВАШ_ЛОГИН * /persistent:yes
```

Пароль не следует вставлять в командную строку: он попадёт в историю.
Для отключения: `net use W: /delete` и отзыв устройства на сайте.

Microsoft объявила встроенный WebClient устаревшим; он не запускается по
умолчанию и может отсутствовать в конкретной сборке Windows. Если штатное
подключение недоступно, нужен поддерживаемый WebDAV-клиент с монтированием диска.
Не включайте Basic Authentication по HTTP и не отключайте проверку сертификата.
У встроенного клиента есть собственный лимит размера файлов (обычно около
50 МБ), независимо от квоты сайта. Изменения реестра автоматически не выполняются.
Сетевой диск не является офлайн-синхронизацией: для работы требуется соединение.

## Пароли устройств

- Создание только администратором для своего облака, с CSRF-защитой и повторным
  подтверждением текущего пароля аккаунта через HTTPS.
- 256 случайных бит секрета, показ однократно. Сохраняется SHA-256, не сам пароль.
- Отдельное название устройства, режим только чтения или чтения/изменения,
  срок 30, 90 или 365 дней, максимум 20 записей на владельца.
- Основной пароль и браузерная сессия не дают доступа к WebDAV.
- Отзыв блокирует новые запросы; перед завершением записи доступ проверяется
  повторно. Уже скачанные копии и начатые скачивания отозвать нельзя.
- Смена пароля аккаунта инвалидирует ранее выпущенные пароли устройств.
  Удалённому пользователю или пользователю без роли администратора доступ запрещён.
- Дата последнего использования сохраняется не чаще раза в час. В журнале
  безопасности фиксируются создание/отзыв и успешные изменяющие операции, без
  паролей, содержимого файлов и заголовков Authorization.
- Пароли доступа не дают права входить на сайт или менять настройки аккаунта.
  Это ограниченные по назначению секреты, а не сквозное шифрование файлов.

## Сохранение файлов

Поддерживаются список папок, скачивание с Range, загрузка, создание папок,
копирование, перемещение, переименование, удаление и временные DAV-блокировки.
Файлы и папки доступны сразу на сайте. Корзина через WebDAV не показывается.

Удаление переносит данные в корзину. При замене файла старая версия также
остаётся в корзине, а новый оригинал получает новый внутренний идентификатор.
**Прямая публичная ссылка на старую версию закрывается**; ссылка на содержащую
папку продолжает показывать актуальное содержимое. Корзина входит в квоту;
регулярные сохранения больших файлов могут потребовать её очистки на сайте.

Операции выполняются на снимке метаданных и временных файлах. Прерванная
загрузка, неудачное копирование или ошибка сохранения не публикуют частичный
результат. Конкурирующее изменение этого же личного облака отклоняется с 409:
обновите папку и повторите операцию. Это консервативная проверка всего облака
владельца, а не совместное редактирование документа. If-Match/If-None-Match
проверяются перед изменением. Блокировки DAV действуют между DAV-клиентами,
не запрещают редактирование через сайт и исчезают при перезапуске; максимум
пять минут с продлением клиентом. Произвольные дополнительные DAV-свойства
(PROPPATCH) не сохраняются. Листинг PROPFIND ограничен Depth 0/1.

Временные `.dav-*.tmp` создаются вне публичной статики и удаляются по завершении
запроса. После аварии могут остаться временные или неучтённые оригиналы;
не удаляйте их без сверки с метаданными и резервной копии.

## Включение на сервере

По умолчанию WebDAV **выключен**. Достаточно переменных окружения процесса:

```text
WORKSERVICE_DAV_ORIGIN=https://appworks.avayusstroi.by
WORKSERVICE_DAV_TRUSTED_PROXIES=127.0.0.1/32,::1/128
APP_COOKIE_SECURE=true
WORKSERVICE_LISTEN_ADDR=127.0.0.1:8099
```

Адреса proxy и прослушивания выше являются **примером** для router на той же машине.
Нужно указать фактический непосредственный адрес router; при Docker это может
быть адрес контейнера. Не доверяйте всей сети, 0.0.0.0/0, произвольному
X-Forwarded-For или заголовку от клиента. Неверная конфигурация отключает DAV.
Проверяются Host и TLS либо точный `X-Forwarded-Proto: https` от доверенного peer.

Сервис router должен:

1. Иметь действующий TLS-сертификат домена и не передавать DAV по HTTP.
2. Передавать исходный Host, Authorization, Destination, Depth, If, If-Match,
   If-None-Match, Lock-Token, Timeout, Range и нестандартные HTTP-методы без
   перенаправления на страницу входа или удаления префикса `/dav`.
3. **Перезаписывать**, а не дополнять присланный клиентом X-Forwarded-Proto,
   используя фактическое TLS-соединение router. Не принимать внешний HTTP
   за HTTPS на основании заголовка клиента.
4. Не кэшировать DAV и `/cloud/devices`, не журналировать тела запросов с
   паролями/файлами или Authorization. Ограничить размер и время запросов.
5. Ограничить прямой доступ извне к порту приложения 8099: браузерный вход
   тоже должен выполняться через HTTPS. Secure-cookie сам по себе не закрывает
   HTTP-порт и не защищает пароль, введённый на HTTP-странице.

Дополнительно в приложении: предел 8 одновременных DAV-запросов, 10 минут на
запрос, ограничение тела XML 1 МиБ и прежний лимит файла. Счётчики попыток
ограничены по памяти. Счётчики IP используют реальный peer, так что за router
они общие; для разделения клиентов добавьте rate limit на самом router.

Метаданные устройств входят в `cloud_devices.json` выбранного хранилища,
резервные копии и миграцию JSON/SQLite. Восстановление старой резервной копии
может восстановить старые права: после восстановления отзовите прежние устройства.

Для постоянного запуска предпочтителен собранный бинарник под systemd с
непривилегированным пользователем и отдельным EnvironmentFile, а не `go run`.
Перевод способа запуска, firewall, proxy и обновление рабочего сайта требуют
отдельного согласования; эта доработка их не меняет.

## Проверка

`go test ./...`, `go vet ./...`. Интеграционные тесты проходят на JSON и SQLite,
проверяют операции DAV, TLS/proxy, CSRF, пароли, отзыв, read-only, чужое облако,
обрыв загрузки, блокировки и конфликтующие изменения. Browser-проверка:
`scripts/cloud-dav-check.cjs`, только на изолированном тестовом сервере.
Для реального выпуска дополнительно проверить Windows WebClient и выбранное
iOS-приложение на целевых устройствах: протокольные тесты их не заменяют.
